## B. GUIの起動と画面構成

起動方法は3つ。**batがダブルクリックで動かない場合は方法1/3を使ってください**（`.bat`関連付けの問題で、batの中身に関わらず動きません）。

- **方法1（最も確実・メニュー式）**：Anaconda Prompt で
  ```
  cd /d C:\Users\612316\Downloads\06_GEO\monitoring

  ```
  → メニューが開き、番号で「GUI起動／接続診断／データ全削除／データ選択削除」を選べます。
- **方法2（ショートカットでダブルクリック）**：デスクトップで右クリック→新規作成→ショートカット→
  項目の場所に `"C:\work\anaconda_install\python.exe" "C:\Users\612316\Downloads\06_GEO\monitoring\run.py"`
  を貼り付けて作成。以降そのショートカットをダブルクリックでメニューが開く（batを使わない）。

## D. 本番：手動実行の手順

1. 「観測するLLM」＝ Claude Sonnet 5 にチェック。
2. **ドライランのチェックを外す**（本番はオフ）。
3. 実行範囲：
   - 全78問で実行 → 「事業ドメインを絞る」はオフ。
   - 一部だけ試す → オンにして C5 などを選択。
4. **開始タイミング**：すぐ実行／●分後に実行 を選択。
5. **繰り返し**：
   - 「1回のみ」＝通常。
   - 「●分おきに〇回」＝**AIの回答のブレ（安定性）を測りたいとき**（例：10分おきに3回）。
6. **「▶ 実行する」** をクリック。
7. 完了後、右側「レポート」→ **「📊 ダッシュボードを開く」** で結果を確認。

> **初回の本番テスト推奨**：Claude／C5／1回（=8コール）で正常に出現判定・レポートが出るか確認してから、全78問に広げると安全です。

## E. 本番：自動実行（定期）の設定手順

1. 「観測するLLM」＝ Claude Sonnet 5。ドライランはオフ。
2. **実行モード＝自動実行（定期）** を選択 → 「実行頻度」欄が表示される。
3. **開始タイミング**：すぐ1回目を実行／●分後に1回目を実行。
4. **繰り返し**：1回のみ／●分おきに〇回（各タイミングごとの実行回数）。
5. **実行頻度** を選択（例）：
   - 「月初 第1営業日」＋時刻 09:00
   - 「毎週 月曜」＋時刻 09:00
   - 「毎月 第5営業日」など
   - 選ぶと **次回予定日時のプレビュー** が表示されます。
   - 「**土日・祝日なら翌営業日にずらす**」にチェックすると、該当日が休みのとき翌営業日の同じ時刻に実行します
     （例：第1火曜が祝日なら水曜）。`config/schedule.json` の `rule.holiday_shift: "next_business_day"`。
     ※ 2026-10 時点の設定：第1火曜 13:30（土日・祝日なら翌営業日）。
6. **「▶ 自動実行を設定」** をクリック。→ 右側が「自動実行 設定済」になり、次回予定が表示。
7. **黒いウィンドウは開いたまま**にしておく（閉じると停止）。
8. 停止したいとき：**「■ 自動実行を停止」** をクリック。

> 実行中の回を途中で止めたいとき：**「中断」** ボタン（現在の回の区切りで停止）。

## F. レポートの見方（3層）

「📊 ダッシュボードを開く」で表示（`data/dashboard.html`）。

- **時系列トレンド タブ**（複数タイミングの推移）
  - 上部KPI：最新の全体出現率（平均）、SD（ブレ）、安定性スコア、前回比、初回比。
  - グラフ：全体出現率の推移（平均±SDの帯）、モデル別・事業別の推移。
  - **施策への示唆**：コンテンツ空白（低出現ドメイン）、あと一歩（ブレている質問）、低下/改善ドメイン。
  - 前回比の変動テーブル。
- **タイミング詳細 タブ**（1タイミングのブレ分析）
  - タイミングを選択 → 平均±SD、最小〜最大、安定性スコア、回ごとの出現率、モデル別平均±SD。
  - **出現が安定していない質問**（何回中何回出たか）→ ページ改善の優先候補。

**rowデータ（回答全文）** が必要なとき：GUIの「⬇ 全rowデータCSV」または履歴表の各行「CSV」からダウンロード（Excelで開けます・UTF-8 BOM）。

## I. トラブルシューティング

| 症状 | 対処 |
|---|---|
| **batがダブルクリックで動かない** | Windowsの`.bat`関連付けの問題（全batが動かない）。`python run.py`、またはrun.pyへのショートカットを使う（B章 方法1/2）。関連付けを直すなら管理者cmdで `assoc .bat=batfile` と `ftype batfile="%1" %*` |
| **SSLエラー / certificate verify failed / Connection error** | 社内CAがcertifi未収録が原因。`pip install truststore`（requirements.txtに同梱）。導入後 `python src\diag_connection.py` で [4]「成功」を確認 |
| ブラウザが開かない | 黒いウィンドウ内のURL（`http://127.0.0.1:8765/`）を手動でブラウザに貼り付け |
| Claude の回答が空（分析ダッシュボードで「Claude 未計測」・有効行が減る） | Claude は答える前に内部で考える（思考）部分があり、思考だけで回答の長さの上限（`config/models.json` の `max_tokens`）を使い切ると本文が空になる。2026-09-30 に 800 → 2000 に変更。原因は `data/logs/log_*.jsonl` の `response_meta`（`stop_reason`＝`max_tokens` かつ `block_types` に `text` が無ければ上限不足）で確認できる。GUI の進捗にも「空（max_tokens／出力 2000/2000）」と出る。続く場合は `max_tokens` をさらに上げる |
| 「python が見つからない」 | Python未インストール／PATH未設定。再インストール時に「Add to PATH」を有効化 |
| 実行するとエラー（APIキー） | `.env` のキーを確認。Claude以外を選んでいる場合はそのキー未設定が原因。Claudeのみ選択で実行 |
| 出現率が毎回0% | ドライランがオンのままの可能性。オフにして再実行 |
| 祝日が考慮されない | `jpholiday` 未導入。`pip install jpholiday` で導入 |
| 自動実行が動かない | GUIの黒いウィンドウを閉じていないか確認（常駐が必要） |
| 「🔎 分析ダッシュボードを開く」がグレーのまま | `config/analysis_link.json` で `enabled:false` になっているか、ファイルの形式が正しくない。ボタンにマウスを乗せると理由が出る（K章）。ファイルが無い場合は Box の analysis.html を開く設定で有効になります |
| 分析ダッシュボードの上部に「前回生成分を表示」と出る | 最新化（generate.py）に失敗、または GEO-analysis が見つからない。`data/analysis_link.log` に終了コードとエラー末尾が残る（K章） |

## J. 運用方式とセキュリティ

**採用方式：BOX共有フォルダから直接実行（共有キー方式）**
- 共有フォルダ：`%USERPROFILE%\Box\事業推進Div□\DX推進課\生成AI\monitoring`
  （`%USERPROFILE%` は各自の `C:\Users\<本人>` に自動解決。全メンバー共通で使えるパス）
- 各メンバーは初回のみ `pip install -r requirements.txt`（ローカルのPythonにパッケージ導入）。
- 実行は `python run.py`（またはrun.pyへのショートカット）。詳細は「メンバー向けセットアップ手順」。
- APIキーは共有フォルダの `.env` に1本の共有キーを設定して全員で使用。`data/` も共有フォルダに保存＝全員で共有。

**セキュリティ上の注意（この方式の前提）**
- 共有フォルダの `.env` の鍵は、フォルダ閲覧者全員が見られる。**アクセス権を必要なメンバーに限定**すること。
- 共有用は**この用途専用のAPIキー**を1本発行して使う（影響の局所化・失効しやすさのため）。管理は管理者（中島）。
- チャット等で露出した鍵は、Anthropic Console で**失効・再発行**を推奨。
- 複数人の同時実行は `data/` が競合し得る。実行タイミングを分ける／担当者を決める運用が安全。

## K. 分析ダッシュボード（関係者向けの入口）

関係者が見る入口は **GEO-analysis の `analysis.html`（分析ダッシュボード）** に一本化しています。
定点観測の GUI からワンクリックで最新版を開けます。GEO-analysis のコードは変更せず、その CLI（`python generate.py`）を外部プロセスとして呼ぶだけの疎結合です。

### K-1. 開き方

- GUI 右側「レポート」→ **「🔎 分析ダッシュボードを開く（関係者向け）」**。別タブで開きます。
  - 押すと最新の結果 CSV で `analysis.html` を再生成し（Box の `GEO-analysis\analysis.html` にもコピー）、それを表示します。数十秒かかることがあり、その間ボタンは「⏳ 生成中…」になり二重クリックできません。
  - ボタンの下に **最終生成日時** と **表示元（ローカル（GEO-analysis）／Box 共有版）** が出ます。
- 「📊 ダッシュボード」「💡 示唆レポート」の上部にも「関係者向けの分析・示唆は **分析ダッシュボード** へ」のリンク帯があります。
  - GUI 経由で開いているときは GUI の分析ダッシュボード（最新化あり）へ、ファイルを直接開いたときは Box 上の `analysis.html` へ移動します。
  - リンク帯は dashboard.html / insights.html を**生成したとき**に設定から埋め込みます（設定が無ければ出ません）。

### K-2. 自動最新化の仕組み

| タイミング | 動き |
|---|---|
| GUI のボタンを押したとき | `regenerate_on_open: true` なら `generate.py` を実行 → 表示。失敗しても前回の `analysis.html` があればそれを表示し、上部に「最新化に失敗したため前回生成分を表示」と注記 |
| 定期の自動実行（`run_scheduled`）の後 | Box 同期（box_sync）の後に `regenerate_after_scheduled_run: true` なら `generate.py` を実行（Box へもコピー）。**ドライラン時は実行しない**。失敗しても自動実行は成功扱い（box_sync と同じく非致命的） |

- 結果は `data/run_log.txt` に1行（例：`分析ダッシュボード再生成：成功／再生成しました／0.4秒`）。
- 詳細（終了コード・stdout/stderr の末尾）は `data/analysis_link.log` に残ります。
- 手動で状態確認・再生成：`python src\analysis_link.py`（状態表示）／`python src\analysis_link.py --regen`（再生成＋Box反映）。

### K-3. 設定（`config/analysis_link.json`）

`config/analysis_link.json.example` をコピーして `config/analysis_link.json` を作成します。
**個人環境のパスを含むため Git 管理外（.gitignore）で、Box へのプログラム反映の対象外**です（各PCで作る）。
**このファイルが無い PC（Box 上の GEO フォルダから GUI を開いた場合・メンバー PC）でも、ボタンは有効**です。その場合は生成せず、
Box の `事業推進Div□\DX推進課\生成AI\GEO-analysis\analysis.html`（運用者 PC が生成したもの）を開くだけになります
（Box の GEO-analysis フォルダにある古い generate.py で作り直して最新版を上書きしないため）。

```json
{
  "enabled": true,
  "analysis_repo": "C:\\Users\\612316\\Documents\\GitHub\\GEO-analysis",
  "generate_py": "generate.py",
  "analysis_html": "analysis.html",
  "fallback_html": "%USERPROFILE%\\Box\\事業推進Div□\\DX推進課\\生成AI\\GEO-analysis\\analysis.html",
  "regenerate_on_open": true,
  "regenerate_after_scheduled_run": true,
  "timeout_sec": 180
}
```

| 項目 | 意味 |
|---|---|
| `enabled` | `false` で関連機能をすべて無効（ボタンはグレーアウト、理由はツールチップ） |
| `analysis_repo` | GEO-analysis リポジトリの場所。`generate.py` はここを作業フォルダにして実行 |
| `generate_py` / `analysis_html` | `analysis_repo` からの相対パス |
| `fallback_html` | ローカルに `analysis.html` が無いときに開く Box 上のファイル |
| `regenerate_on_open` | ボタン押下時に再生成するか |
| `regenerate_after_scheduled_run` | 定期自動実行の後に再生成するか |
| `timeout_sec` | `generate.py` のタイムアウト（秒） |

- パス中の `%USERPROFILE%` などの環境変数は自動で展開されます。
- 開く HTML の優先順：① `analysis_repo\analysis_html` → ② `fallback_html` → ③ どちらも無ければ対処方法の案内ページ。
- Box へのコピー先は GEO-analysis 側の `config.json` の `share_dirs` で決まります（monitoring 側では設定しません）。

### K-4. GEO-analysis が無い環境（メンバーPCなど）

- `analysis_repo` が見つからない場合は**生成せず**、Box 上の `analysis.html`（`fallback_html`）を表示するだけです。
  上部に「GEO-analysis が見つからないため最新化せず、前回生成分を表示しています｜表示中：Box 版」と出ます。
- **生成は運用者PC（GEO-analysis がある PC）のみ**。メンバーは運用者PCの自動実行で更新された Box 版を閲覧します。
- `analysis_link.json` 自体が無ければボタンはグレーアウトし、ほかの機能は通常どおり使えます。

## L. Google 検索チェック（毎月・全問）

Claude と同じ設問を Google でも調べ、分析ダッシュボードの「Google参考値」タブに反映します（設計：`Google参考値観測_設計_v1.md` §5）。
**検索は人が行います。** ブックマークレット「GEO記録」が、表示中の検索結果ページから上位10件のドメイン・タイトルと
AI による概要（AI Overview）の有無・引用元を読み取り、この GUI に記録します。プログラムから Google に検索を送ることはしません（利用規約・CAPTCHA のため）。

### L-1. 初回だけ：ブックマークレットを登録
1. GUI（`monitoring_gui.bat`）を起動し、画面下の **「Google 検索チェック（毎月・全問）」** を開く。
2. Chrome のブックマークバーを表示（Ctrl+Shift+B）し、**「🔖 GEO記録」ボタンをブックマークバーへドラッグ**する。
   - ドラッグできない場合：「コードをコピー」→ ブックマークを新規作成し、URL 欄に貼り付け（名前は GEO記録）。
3. シークレットウィンドウでもブックマークバーが表示されることを確認する。
- ブックマークレットには GUI のポート番号（通常 8765）が入っています。GUI の画面に表示されるポートが変わったときは登録し直してください。

### L-2. 毎月の手順（約270件・70〜90分。途中で止めて再開できます）
1. GUI を起動したまま、**Chrome のシークレットウィンドウ（Ctrl+Shift+N・Google 未ログイン）** で、パネルに表示される URL
   （例 `http://127.0.0.1:8765/gc/next`）を開く → まだ記録していない最初の語の Google 検索結果が開く。
2. 結果を目で確認（AI による概要が「もっと見る」なら開く）→ ブックマークバーの **「GEO記録」** を押す。
3. 記録画面に「自社の順位／AI による概要／上位10件内の競合／読み取った件数」が出る → **15秒後に次の検索が自動で開く**（すぐ進むときは「次の検索へ」）。
   - 記録画面の「自動で次へ進む：ON/OFF」で一時停止できます。再開は同じ URL（`/gc/next`）を開くだけです。
4. **30件ごとに自動で進むのが止まり、休憩の案内が出ます。** 10分ほど休憩してから「次の検索へ」を押してください（10分以上あけると件数は数え直し）。
5. 全件終わると「すべて記録済み」の画面になります。GUI の一覧で結果を確認できます。
- **ペースの目安**：短時間に検索が集中すると Google に止められます（2026-09-29 は約40分で183件を連続で検索した直後に 403 になりました）。1日に2〜3回に分け、30件ごとに休憩してください。
- 対象月は**実施した月**です（例：9月末に実施 → 2026-09）。同じ語を記録し直すと上書きされます。
- 環境をそろえる：同じ PC・シークレットウィンドウ・未ログイン。

### L-3. うまくいかないとき
| 症状 | 対処 |
|---|---|
| 記録画面に移動しない | データはクリップボードにもコピーされています。GUI の「貼り付けで記録」に貼り付けて「記録」。 |
| 「読み取った件数 0 件」の警告 | Google の画面が変わった可能性。GUI の一覧で「手入力」（自社の順位・AI による概要の有無など）で記録。 |
| 「今月の検索リストにない語」 | 手で別の語を検索した場合。記録はされますが集計には使われません。 |
| 記録を消したい | GUI の一覧で「取消」。もう一度検索して記録し直せます。 |
| CAPTCHA（私はロボットではありません）が出る | 人が解いて続けてください。続く場合は時間を空けて再開。 |
| Google の検索結果が 403 になる | 短時間に検索しすぎて Google に一時的に止められています。**その日はやめて、数時間〜翌日に再開**（`/gc/next` で続きから）。記録済みの分は消えません。 |

### L-5. 競合・媒体を手動で追加する（競合・媒体の辞書）
GUI のパネル内「**競合・媒体の辞書（検索結果の判定）**」を開きます。
- **種類**：「競合」＝競合として数える会社。「媒体」＝PR TIMES・YouTube・note など情報を載せる先（競合には数えず、分析ダッシュボードの「外部での言及を増やす」に載せる先の候補として出る）。
- グループサイト（onward-hd.co.jp）は自社にも競合にも数えず、分析ダッシュボードで別枠表示します（辞書には登録できません）。
1. 種類・名前とドメイン（例 `nagaileben.co.jp`。複数はカンマ区切り、`https://` や `www.` は付けても可）を入れて「追加・更新」。
   - 「追加の候補」に、記録済みの上位10件によく出るが未登録のドメインが出ます。クリックするとドメイン欄に入ります。
   - 「AI 回答の競合辞書（competitors.json）にも追加」にチェックすると、Claude の回答の社名抽出（示唆レポート）にも登録されます（表記ゆれも入力可）。
2. 登録・削除すると、**記録済みの検索結果の競合判定を自動でやり直します**（手入力の記録は変わりません）。
- 既存の会社を直すときは「編集」→ 内容を直して「追加・更新」。同じドメインを別の会社に登録すると、元の会社からは外れます。自社ドメインは登録できません。
- 削除は検索結果の判定用の辞書からだけ行い、competitors.json からは削除しません（必要なら手で編集）。
- **編集は運用者 PC（GitHub 側）の GUI で行ってください。** Box 上のコピーで編集しても、Box 同期で GitHub 側には取り込まれません。
- 分析ダッシュボードへの反映：GUI の「🔎 分析ダッシュボードを開く」で再生成したとき、または GEO-analysis の自動更新タスク
  （検索チェックの CSV の更新も検知）で反映されます。Box の GEO フォルダへは次回の Box 同期でコピーされます。
- 検索の対象語：`config/google_keywords.csv`（設問ごとの観測キーワード）と、questions.json / questions_set2.json の設問文。

## M. 回答の読み取り判定（最後のおすすめに残るか・推される理由）

保存済みの AI の回答を、別の AI（判定 AI。既定は Claude Opus 5.5）に読ませて、次を判定します。
- 回答の形：候補を並べて最後に絞り込んだ（絞り込みあり）／並べただけ（一覧のみ）／候補を挙げていない（候補なし）／答えられていない（回答不能）
- 回答に挙がった会社と、最後のおすすめに残ったか
- 各社が推される理由（`config/competitors.json` の attributes の観点から選ぶ）

### M-1. 実行のしかた
- メニュー：`python run.py` →「5) 回答の読み取り判定」。判定する件数を表示したあと、y で実行し、レポートをブラウザで開きます。
- コマンド（monitoring フォルダで）：
  - `python src/answer_judge.py --dry-run` … 新たに判定する件数だけ表示（課金なし）
  - `python src/answer_judge.py --open` … 直近5回分を判定してレポートを開く
  - `python src/answer_judge.py --limit 10` … 新たに判定するのは10件まで（お試し）
- 費用の目安：1回答あたり約0.03ドル（2026-10 時点の実測）。138問×1回分で約4ドル。
  **判定済みの回答は保存してあり、二度は判定しません**（`data/judgments/judgments.jsonl`。Git 管理外）。

### M-2. レポート（`data/judge_report.html`）
1. 名前が出たあと、最後のおすすめまで残った割合（自社・競合）
2. 立場別の自社の扱い（1社だけおすすめ／他社と並んでおすすめ／おすすめから外れる／並ぶだけ／名前が出ない）
3. 会社ごとの推される理由
4. おすすめの顔ぶれが固まっているか（同じ質問を3回以上判定できたもの。最も多く残った会社が8割以上の回で同じなら「固まっている」）
5. Google参考値との突き合わせ（質問ごと）：最新月の検索チェック（`data/google_check/google_check_YYYY-MM.csv`）と設問IDで突き合わせ、
   「Googleでは引用・Claudeでは出ない」「Google検索では上位・Claudeでは出ない」「どちらにも出ない」「どちらにも出る」「Claudeだけ出る」「検索チェック未記録」に分けます。
   Claude はその期間に1回でも自社の名前が出れば「出る」、Google は設問文・観測キーワードのどれかでAIによる概要に引用されたか／上位10件に入ったかで見ます。
6. 施策の示唆（上の集計からルールで作成）

### M-3. 設定（`config/judge.json`）
- `model` / `effort`：判定 AI のモデルと考える深さ。
- `votes`：1つの回答を何回判定するか。3 にすると多数決（ぶれは減るが費用は3倍）。
- `report_runs`：レポートの対象にする直近の回数（既定5）。
- `auto_after_run`：true にすると、定期実行・GUI 実行のあとに新しい回答を自動で判定します（既定 false）。
- `own_aliases_extra`：自社とみなす表記の追加（旧社名など）。detection_keywords.json の primary / secondary とあわせて使います。
- 判定はAIによるもので、読み違いがあり得ます。重要な判断の前には回答の原文も確認してください。
