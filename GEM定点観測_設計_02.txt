# 生成AI回答への自社出現 定点観測システム設計書 v2
## 株式会社オンワードコーポレートデザイン

更新日：2026年6月30日（v1からの主な変更：軸B再設計・空間ビジネス追加・ABM観測追加・ECサイト別計測追加・モノ→コトの事業文脈更新）

---

## 1. 概要・目的

生成AIが業務課題を問われた際に、**オンワードコーポレートデザイン（各事業・ブランド）が回答に出現するか**を定量的・継続的に計測する。

計測結果を以下の戦略に反映する：
- **GEO（Generative Engine Optimization）：** AIに推薦される企業としての認知向上
- **ABM（Account-Based Marketing）最適化：** ターゲット企業セグメントにおける出現状況の把握と、事業横断LTV向上への示唆
- **コト提供シフトの評価：** モノ売りではなく「顧客ブランド支援」の文脈で出現できているかの検証

## 6. 測定・スコアリング設計

### 6.1 観測指標

| 指標名 | 算出方法 | 分析用途 |
|---|---|---|
| **出現率（全体）** | 出現した回答数 ÷ 総質問数 × 100（%） | 全体の存在感 |
| **事業別出現率** | C軸別の出現率 | 事業ごとの認知ギャップ把握 |
| **モデル別出現率** | LLMモデルごとの出現率 | モデルによる差異把握 |
| **質問タイプ別出現率** | A軸別の出現率 | どの検索意図で出やすいか |
| **言及ポジション** | 推薦リストの何番目に登場したか | 推薦順位の把握 |
| **ABMスコア** | C7質問の出現率（事業横断文脈での認知） | LTV施策の優先度判断 |
| **空間ビジネス出現率** | C6質問の出現率 | 新事業文脈での認知把握 |
| **ECサイト出現率** | C3-EC質問の出現率 | クリニック向け認知の別管理 |

### 6.2 出現判定キーワード

| 観測エンティティ | 判定キーワード（部分一致） |
|---|---|
| 法人全体 | `オンワードコーポレートデザイン` / `Onward Corporate Design` / `オンワードCD` |
| メディカルブランド | `Raffiria` / `ラフィーリア` |
| ECサイト | `onward-raffiria.shop` |

### 6.3 ABM観測の補足指標

ABM最適化に向けて以下の分析も実施する：

- **ターゲット企業セグメント別の出現文脈**：「大企業向け」「系列病院グループ向け」等の文脈で出現しているか
- **クロスサービス言及率**：複数事業が同一回答内で言及される割合（=横断認知の指標）
- **A7（ABM横断型）質問での出現率**：LTV拡大に最も直結する質問での出現を重点モニタリング

### 7.4 質問リストの変更について

**質問文は実装後でも自由に変更できます。** 質問リストは`questions.json`（外部ファイル）として管理するため、Pythonコードを触らずにテキストエディタで編集可能です。

変更が推奨されるタイミング：
- 新しいコンテンツ（コラム・事例記事）を公開したとき → その記事に対応する質問を追加
- GEO施策の効果を検証したいとき → 施策に対応した質問を一時的に追加
- 事業戦略が変わったとき → ステークホルダーや質問タイプを見直し
- 質問に対するLLMの回答品質が低いと感じたとき → 質問文を言い換えてA/Bテスト

**バージョン管理推奨：** `questions_v1.json` `questions_v2.json` のように版管理することで、質問変更前後の出現率変化も追跡できます。
