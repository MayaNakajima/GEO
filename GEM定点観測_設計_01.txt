# 生成AI回答への自社出現 定点観測システム設計書
## 株式会社オンワードコーポレートデザイン

作成日：2026年6月30日

---

## 1. 概要・目的

生成AIが「企業のユニフォームを探している」「医療ウェアを発注したい」などの業務課題を問われた際に、**オンワードコーポレートデザイン（および各事業・ブランド）が回答に出現するか**を定量的・継続的に計測する。

計測結果をもとに「AIが推薦する企業」としての認知状況を把握し、コンテンツマーケティングやSEO・GEO（Generative Engine Optimization）戦略に反映することが目的。

## 3. 質問分類フレームワーク

### 3.1 分類軸の定義

質問は**3軸**で分類し、掛け合わせで分析する。

---

**軸A：質問タイプ（検索意図）** ← 最重要軸

| コード | タイプ | 概要 | 例 |
|---|---|---|---|
| A1 | **業者・サービス推薦型** | 具体的な発注先・会社名を聞く | 「企業ユニフォームを頼める会社は？」 |
| A2 | **課題解決型** | 業務課題の解決策を聞く | 「看護師の離職率を下げるには？」 |
| A3 | **比較・選定型** | 選定基準・ポイントを聞く | 「ユニフォームを発注する際の比較軸は？」 |
| A4 | **トレンド・市場情報型** | 業界動向・最新情報を聞く | 「医療ウェアの最新トレンドは？」 |
| A5 | **事例・実績型** | 成功事例・導入例を聞く | 「制服リニューアルで入学者が増えた学校の事例は？」 |
| A6 | **企業情報直接型** | 社名を直接入力して聞く | 「オンワードコーポレートデザインはどんな会社？」 |

> **分析上の意義：** A1・A3が最も購買意欲が高い質問。A2・A5はコンテンツ施策の評価に有効。A6は指名認知の確認。

## 4. 測定・スコアリング設計

### 4.1 観測指標

| 指標名 | 算出方法 | 意味 |
|---|---|---|
| **出現率（Mention Rate）** | 出現した回答数 ÷ 総質問数 × 100（%） | 全体での存在感 |
| **事業別出現率** | 各C軸別の出現率 | 事業ごとの認知ギャップ把握 |
| **モデル別出現率** | 各LLMモデルごとの出現率 | モデルによる差異の把握 |
| **質問タイプ別出現率** | 各A軸別の出現率 | どの検索意図で出やすいか |
| **言及ポジション** | 最初に言及された順位（1位〜n位以下、なし） | 推薦順位の把握 |
| **言及文脈スコア** | ポジティブ/ニュートラル/ネガティブ（任意） | 紹介される文脈の質 |

### 4.2 出現判定ロジック

以下のキーワードが回答テキストに含まれるかを判定（部分一致）：

- `オンワードコーポレートデザイン`
- `Onward Corporate Design`
- `オンワードCD`
- `Raffiria`（ラフィーリア）
- `onward-cd.co.jp`

さらに言及ポジションは、出現位置が「推薦リストの何番目か」を判定（1番目に登場 → Position 1）。

## 5. システム設計（自動化エージェント）

### 5.1 全体フロー

```
[質問リスト（JSON/CSV）]
        ↓
[Pythonエージェント（スケジュール実行）]
        ↓ 各LLM APIに並列リクエスト
[Claude API / GPT-4o API / Gemini API / Perplexity API]
        ↓ 回答を取得
[出現判定・ポジション抽出]
        ↓
[結果をCSV/スプレッドシートに記録]
        ↓
[月次サマリーレポート自動生成（Claude API）]
        ↓
[メール or Slack通知]
```

### 5.2 対象LLMモデル（推奨）

| 優先度 | モデル | API | 備考 |
|---|---|---|---|
| ◎ 必須 | Claude 3.5 Sonnet (claude-sonnet-4-6) | Anthropic API | 自社モデルとして基準値に |
| ◎ 必須 | GPT-4o | OpenAI API | 市場シェアが最大 |
| ◎ 必須 | Gemini 1.5 Pro | Google AI API | Google検索連動の影響大 |
| ○ 推奨 | Perplexity Sonar Pro | Perplexity API | リアルタイム検索型。GEO観測に最適 |
| △ 任意 | Grok 3 | xAI API | SNSデータ学習の影響を確認 |

> **Perplexityは特に重要：** 検索連動型のため、SEOコンテンツ施策との相関が見やすい。

### 5.3 実装コンポーネント

```
project/
├── config/
│   ├── questions.json        # 質問リスト（分類コード付き）
│   ├── models.json           # 使用するLLMモデルと設定
│   └── detection_keywords.json  # 出現判定キーワード
├── src/
│   ├── runner.py             # メイン実行スクリプト
│   ├── llm_client.py         # 各LLM API呼び出し（共通インターフェース）
│   ├── detector.py           # 出現判定・ポジション抽出
│   ├── logger.py             # CSV記録・ログ管理
│   └── reporter.py           # 月次レポート生成
├── data/
│   ├── results/              # 実行ごとの生データ（YYYY-MM-DD.csv）
│   └── reports/              # 月次レポート
└── .env                      # APIキー（環境変数）
```

## 6. 自動化スケジュール

### 6.1 推奨サイクル

| 実行タイミング | 目的 | 実行内容 |
|---|---|---|
| **月次（月初）** | 定点観測の主サイクル | 全質問×全モデルを実行。月次レポート生成・通知 |
| **四半期** | トレンド分析 | 3ヶ月間の出現率推移グラフ作成。施策効果の確認 |
| **イベント時** | 施策効果測定 | コンテンツ公開・プレスリリース後に単発実行 |

### 6.2 Claudeの定期実行スケジュール設定

Claude（Coworkモード）のスケジュール機能を使って月次実行をセットアップできます。設定内容：
- **実行頻度：** 毎月1日 午前9時
- **実行内容：** Pythonスクリプトを起動し、結果レポートをSlack/メールに通知

## 7. レポート・分析設計

### 7.1 月次レポートの構成

1. **エグゼクティブサマリー**
   - 全体出現率（当月 vs 前月比）
   - モデル別ハイライト（最も出現したモデル・最も出現しなかったモデル）

2. **事業別出現率ヒートマップ**
   - 軸C（事業領域）× 軸A（質問タイプ）のマトリクス

3. **モデル別詳細**
   - 各LLMごとの出現率・代表的な言及文脈

4. **注目の質問・回答（ピックアップ）**
   - 出現した回答の本文（文脈確認用）

5. **推奨アクション**
   - 出現率が低い事業・質問タイプへのコンテンツ施策提案

### 7.2 KPI目標例（初期設定の目安）

| KPI | 現状 | 6ヶ月後目標 | 12ヶ月後目標 |
|---|---|---|---|
| 全体出現率 | 計測開始で把握 | 10%以上 | 20%以上 |
| A1（業者推薦型）出現率 | — | 15%以上 | 30%以上 |
| Perplexityでの出現率 | — | 20%以上 | 40%以上 |
| 出現時のポジション平均 | — | 3位以内 | 2位以内 |

## 8. GEO（Generative Engine Optimization）施策との連動

定点観測の結果を以下の施策フィードバックに活用する。

| 出現率が低い場合の施策 | 内容 |
|---|---|
| **コンテンツ強化** | 出現しない質問タイプ（A1, A2）に対応するコラム・事例記事を追加 |
| **構造化データ対応** | FAQスキーマ・HowToスキーマをサイトに実装し、AIの参照精度を向上 |
| **外部言及の強化** | PR記事・業界メディア掲載でAIの学習データに自社情報を増やす |
| **Perplexity対応** | 検索クエリと連動したコンテンツ設計（検索上位 → Perplexity出現） |
| **Raffiria単独認知強化** | ブランド名「ラフィーリア」単体での露出強化（プレスリリース、専門メディア） |

## 10. 補足：Claudeエージェントによる自動実行について

本システムは **ClaudeのCoworkスケジュール機能** を使って以下のように自動化できます：

1. Pythonスクリプトをサーバー（AWS Lambda / Cloud Run / VPS等）に配置
2. Claudeのスケジュール設定で「毎月1日、Pythonスクリプトを実行してレポートを送信する」をセット
3. Claude自身がスクリプト実行 → 結果をメール/Slackに通知するワークフローを組む

また、Claudeをエージェントとして活用することで、**回答の「言及文脈の質」を自動評価**（単なる出現有無だけでなく、ポジティブな推薦か中立的な言及かを判定）する仕組みも追加可能です。
